# Source: `raw/style-export-sample.json`

User-imported, **complete and untruncated** real style export from the YOOtheme Pro Customizer —
built starting from the official `joline` theme with its own overrides. The second real example of
the `styler.library.{id}` JSON wrapper, after [[sources/how-to-create-style-json]] (which was
truncated). Together they fully specify the mechanism documented in
[[concepts/customizer-less-map]].

## What it states

```json
{
  "style": "joline",
  "less": { "...": "46 variables total" },
  "modified": "2026-07-29T14:55:20.985Z",
  "name": "Sample style"
}
```

## What it confirms (and corrects)

Cross-checked against `raw/yootheme-pro-5.0.33/vendor/assets/uikit-themes/master-joline/_import.less`
and `packages/styler/`:

1. **The wrapper is exactly 4 keys, nothing more.** No truncation this time — resolves the open
   question in [[sources/how-to-create-style-json]].
2. **`style` is the id of the base theme, not a project slug.** `"joline"` matches the real official
   theme at `vendor/assets/uikit-themes/master-joline/`. This **corrects** the assumption made in the
   prior session (that `style` followed the `theme.{slug}.less` project-slug convention from
   `generate-css/SKILL.md`) — that convention applies to the *other* mechanism (physical theme files),
   not this one. `"name": "Sample style"` is the independent, free-form label for this saved style.
3. **`less` is delta-only.** Every override differs from `master-joline/_import.less`'s own default:

   | Variable | `master-joline` default | `sample` override |
   |---|---|---|
   | `@global-font-family` | `'Open Sans'` | `'Jost'` |
   | `@global-font-size` | `15px` | `18px` |
   | `@global-primary-background` | `#BFA279` | `#A75C2F` |
   | `@internal-fonts` | `'Poppins:300,400\|Open+Sans:300\|Lora'` | `~'Cormorant+Garamond:400,500,600,700\|Jost:300,400,500\|Lato'` |

   No variable identical to the base default is repeated. This **corrects** the prior assumption that
   `less` held absolute values against a default UIkit theme.
4. **Every one of the 46 overridden variables is a real LESS variable** — verified by an exhaustive
   grep of each key against `raw/yootheme-pro-5.0.33` `.less` sources: zero not found. Some
   (`@card-border-radius`, `@navbar-gap-m`) match no named group in `config/styler.php`, reaching the
   Customizer only through its generic "custom variable" text control
   (`config/styler.php`'s trailing `['type' => 'text', 'vars' => '*']`). This **corrects** the prior
   rule requiring every emitted variable to match a `config/styler.php` group.
5. **`@internal-fonts` matches the `ignore` pattern `@internal*` yet is present and load-bearing** —
   proof that `ignore` only hides a variable from the Customizer's grouped UI, it does not mean the
   variable is invalid or absent from real exports. See the Google Fonts gotcha in
   [[concepts/customizer-less-map]].
6. **`@internal-fonts`'s value keeps the LESS tilde-escape (`~'...'`) inside the JSON string itself**
   — `"~'Cormorant+Garamond:...'"`, not stripped for JSON serialization.
7. **`modified` is exactly JS `Date.prototype.toISOString()` output** — `2026-07-29T14:55:20.985Z`,
   millisecond precision, `Z` suffix.

## What it does not confirm

- How the wrapper behaves for a style built **from scratch**, with no existing base theme (`style`
  pointing to a non-existent/child-only id). Neither this file nor
  [[sources/how-to-create-style-json]] tests that case.
- Whether `@internal-fonts` is regenerated by the Customizer's own JS whenever a font variable
  changes, or whether the user (or design tool that produced this file) set it by hand.
