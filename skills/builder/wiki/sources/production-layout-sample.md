# Production layout export (client site)

A real, production homepage layout exported from the builder, at
`raw/implementations-sample/<client-site>/layout.json` (28 KB), with the project brief
alongside it in `meta.md`. One of a larger set of production layouts available to the user — this
is the first one ingested.

Its value is different in kind from [[sources/yootheme-pro-5.0.33-source]]: the source says what a
prop *can* be, this says what a professional actually *sets*.

## What the site is

A gym — functional training, martial arts, combat sports. Restyling of an existing site.
Brand palette `#FBD808` yellow on `#2F3334` anthracite; Anton for headings, Barlow for body.

## What it contains

The homepage is a layout array of sections. Three `grid` elements appear, each in a different
configuration — which is what makes the file useful as a first ingest:

| Grid | Configuration | Purpose on the page |
|---|---|---|
| 1 | `panel_style: ""`, `show_image: false`, `show_content: false`, `grid_divider: true`, 4 columns | Statistics strip: number + label only, separated by dividers |
| 2 | `panel_style: ""`, `image_border: "rounded"`, `title_element: "h3"`, 1/2/4 columns | Instructor cards: photo, name, role |
| 3 | `panel_style: "card-default"`, `panel_padding: "default"`, `link_style: "text"`, 1/2/4 columns | Course cards: the classic service grid |

Grid 3 is the pattern lifted into [[recipes/service-card-grid]].

## What it confirms

- **`grid` is used for card collections, `panel` for the standalone case.** No `panel` inside a
  `grid` anywhere in the file — `grid` renders its own panels from `grid_item` children. Confirms
  the structural reading in [[elements/grid]]
- **`show_*` props are the real styling lever.** All three grids set them explicitly rather than
  relying on defaults, and grid 1 turns off image *and* content to repurpose a card grid as a
  statistics strip. This is the idiom, not an edge case
- **Defaults are written out.** `margin_top`, `margin_bottom`, `meta_element`, `meta_style`,
  `link_text`, `link_style`, `image_svg_color` all appear at their default values. The builder
  serialises the resolved prop set, not the diff — so an exported layout is a poor guide to which
  props were *deliberately* chosen
- **`link_text: "Read more"` survives on grids with `show_link: false`.** Inert props persist in the
  export. Do not read presence as intent
- Node shape matches the invariants in [[sources/skill-yootheme-json-schema]] throughout: no node
  `id`, `image` and `link` are strings, no `null`

## What is new

- **`show_video`, `show_hover_image`, `show_hover_video`** are set on every grid — three `show_*`
  props absent from the skill's list. Recorded in [[issues/element-types-skill-vs-source]]
- **`grid_item` omits `children` entirely** when it has no children, rather than carrying
  `"children": []`. Both forms are accepted on import; the exporter emits the shorter one
- **`title_element: "div"`** on the statistics grid — a heading style with no heading semantics,
  the correct choice for a number that is not a section heading

## What it contradicts

Nothing. It corroborates the source on every prop it touches.

## Caveats

- Generated by an AI coding agent, not hand-built in the builder UI, though it was imported and run
  on a real installation
- `meta.md` records that several pages are drafts pending client review. That affects the copy, not
  the structure
- Image paths are `PLACEHOLDER_*.jpg` — the layout was delivered before final assets
